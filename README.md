# 💰 Accounting Ledger Application

A Java command-line application that allows users to track financial transactions, record deposits and payments, and generate reports based on transaction history.

I built this project as my first capstone for the Year Up United Java Development program. The main goal was to apply what I've been learning about Java, especially object-oriented programming, collections, file handling, and working with dates.

Instead of using a database, the application stores transactions in a CSV file and loads them into memory using an `ArrayList`. This allows users to access their transaction history while keeping their data saved between sessions.

## 🚀 Features

### 💵 Transaction Management
- **Add Deposits:** Record incoming money with a description, vendor, and amount.
- **Make Payments:** Record outgoing money, automatically stored as negative amounts.
- **Transaction History:** View all recorded transactions.
- **Persistent Storage:** Transactions are saved to `transactions.csv` and loaded when the application starts.
- **Input Validation:** Prevents invalid, zero, or negative amounts from being entered as deposit or payment inputs.

### 📒 Ledger
Users can view their transaction history through three options:

- **All Transactions:** Display the complete transaction history.
- **Deposits:** Display only transactions with positive amounts.
- **Payments:** Display only transactions with negative amounts.

Transaction lists are designed to show the newest records first.

### 📊 Reports
The application includes five reporting options:

| Report | Description |
|---|---|
| Month to Date | Transactions from the beginning of the current month through today |
| Previous Month | Transactions from the entire previous calendar month |
| Year to Date | Transactions from January 1 through today |
| Previous Year | Transactions from the entire previous calendar year |
| Search by Vendor | Find transactions by vendor name, including partial matches |

Reports are generated by filtering transaction objects using Java's date and collection utilities.

## 💾 How Transactions Are Stored

Each transaction contains five properties:

- Date
- Time
- Description
- Vendor
- Amount

All transactions are stored in `DataFiles/transactions.csv` using a pipe (`|`) delimiter.

**Example:**

```csv
date|time|description|vendor|amount
2026-11-01|08:00:00|Monthly Salary|Employer|3500.00
2026-11-02|09:15:00|Coffee|Starbucks|-6.75
2026-11-03|10:00:00|Freelance Website|Client A|750.00
2026-11-04|13:41:08|Laptop Accessories|Amazon|-65.99
```

Positive amounts represent deposits, while negative amounts represent payments.

### How Data Flows

1. When the application starts, it reads existing transactions from the CSV file.
2. Each CSV record is converted into a `Transaction` object.
3. The objects are stored in an `ArrayList<Transaction>`.
4. When a user adds a deposit or payment, a new transaction is written to the CSV and added to the in-memory list.
5. The Ledger and Reports features use the transaction list to filter and display records.

This approach reduces the need to repeatedly read the CSV file whenever a user requests a report.

## ▶️ How to Run the Application

### Prerequisites

- Java Development Kit (JDK) 17 or later
- IntelliJ IDEA or another Java IDE
- Apache Maven (or an IDE with Maven support)

### Steps

**1. Clone the repository**

```bash
git clone <your-repository-url>
```

**2. Open the project**

Open the cloned project folder in IntelliJ IDEA.

**3. Check the data file**

Make sure the following file exists:

```text
DataFiles/transactions.csv
```

The file should include the header:

```csv
date|time|description|vendor|amount
```

**4. Run the application**

Navigate to:

```text
src/main/java/org/pluralsight/LedgerApp.java
```

Run the `main()` method.

The application uses a relative path for the CSV file, so make sure your working directory is set to the project root.

## 🧠 What I Learned

This capstone helped me bring together several Java concepts I've been learning.

Some of the biggest things I worked on were:

- **Object-Oriented Programming:** Using separate classes to organize different responsibilities.
- **Constructor Overloading:** Creating one constructor for new transactions and another for transactions loaded from the CSV file.
- **ArrayLists:** Managing a collection of transaction objects without knowing how many records there will be.
- **File I/O:** Reading CSV records, parsing their values, and appending new transactions without overwriting existing data.
- **Date Handling:** Working with `LocalDate`, `LocalTime`, and `YearMonth` to filter transactions by different reporting periods.
- **Sorting and Filtering:** Using `Comparator` and loops to organize transactions and retrieve matching records.
- **Input Validation:** Handling invalid numeric inputs without crashing the application.

One of the more interesting parts was figuring out how to manage transactions both in memory and in a CSV file. I also spent time thinking about how to organize the classes so that the CLI, transaction logic, and reporting wouldn't all be mixed together.
